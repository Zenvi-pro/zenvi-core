Documentation Style Guide
=========================

Use this style guide when authoring documentation pages so that hierarchy,
spacing, and readability stay consistent.

Headings and structure
----------------------

1. Keep one page-level heading (H1) per page.
2. Use short, action-oriented H2 headings.
3. Break long sections into scannable lists or tables.

Content patterns
----------------

* Prefer concrete, user-centric instructions.
* Explain intent before showing commands.
* Keep examples realistic and concise.

.. note::

   For reusable callouts, code blocks, table formats, and inline badges, see
   :doc:`reference/ui-components`.

Accessibility
-------------

* Write descriptive link text and avoid "click here".
* Ensure tables have meaningful header rows.
* Use callouts to emphasize warnings without relying on color alone.
